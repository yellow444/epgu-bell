# Готовность 0.2.0-rc.4

Поставку можно использовать для пилота с отдельной организацией и своей
сессией. Это чтение уведомлений, а не универсальный контроль статусов услуг.

| Возможность | Состояние |
| --- | --- |
| Пагинация источника | Есть, с пределами и диагностикой остановки |
| Выгрузка SQLite | Курсор, до 1000 записей на страницу, проверка поколения |
| Python-клиент | 17 тестов; пример обмена на 1005 синтетических записях |
| Автоматизации | 8 тестов локальных заготовок Битрикс24, webhook и дайджеста |
| Живая TEST-лента | 66 записей на прежнем кандидате с совпадающими модулями коллектора |
| Точный новый образ rc.4 на живом TEST | Заново не проверялся |
| Пример 1С | Исходный BSL-пример, без запуска на платформе |
| Multi | Закрытая отдельная часть, отсутствует в Free |
| Автоматический вход и PROD | Не приняты |

Остается расширить живую приемку на другие категории, изменение записей,
длинную историю и восстановление сессии во время обхода. Для 1С нужны
отдельный прогон и готовая обработка/расширение. Облачные интеграции
не считаются принятыми по успешным mock-заготовкам.

Обновление существующего каталога не выполняется автоматически. Сначала
сделайте собственную резервную копию данных и отдельно проверьте пакет.
Новая установка использует отдельный --install-root; старая не удаляется.
Перед переключением существующей установки следует остановить только
ее API командой Stop. Автоматического переноса сессии нет.

Подробности: [приемка](../ACCEPTANCE.md), [пагинация](PAGINATION.md),
[интеграции](INTEGRATIONS.md), [автоматизации](AUTOMATION_RECIPES.md).
