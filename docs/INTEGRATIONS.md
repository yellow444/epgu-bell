# Интеграции: 1С, CRM и собственные сервисы

Подключение Битрикс24, n8n/Node-RED, ServiceDesk, краткие оповещения и
связь с оркестратором разобраны в [примерах автоматизации](AUTOMATION_RECIPES.md).
Есть проверяемый генератор заготовок; фактических внешних отправок в нем нет.

Bell выдает уведомления. Система-получатель решает, что с ними делать:
показать оператору, связать с карточкой обращения или поставить задачу
проверить кабинет. По одному заголовку уведомления нельзя надежно объявить
услугу оказанной, исполнительное производство закрытым или срок соблюденным.

## Три способа подключения

| Получатель | Рекомендуемый способ | Что уже есть |
| --- | --- | --- |
| 1С на той же машине | GET локального HTTP API | Пример общего модуля BSL; еще не запускался в 1С |
| 1С на другом сервере | JSON в согласованной папке обмена | Тот же BSL-разбор; пути и права задает администратор |
| CRM или свой сервис | GET локального API либо чтение JSON | Проверенный пример Python с SQLite и повторным импортом |

API слушает loopback. `127.0.0.1` в серверном модуле 1С означает сервер
1С, а не компьютер сотрудника. Не открывайте порт сборщика в локальную сеть
только ради примера. Для разнесенных узлов начните с папки обмена; отдельный
защищенный шлюз потребует своей настройки и приемки.

## Проверить обмен без Госуслуг и без 1С

Команды выполняются из корня репозитория документации. Нужен Python 3.11+,
дополнительные пакеты для этого примера не требуются. Все реквизиты ниже
синтетические. База лежит во временной папке, а не в каталоге репозитория.

```powershell
$demoDb = Join-Path $env:TEMP ('bell-integration-' + [guid]::NewGuid().ToString('N') + '.sqlite3')
python examples/integrations/import_notifications.py --snapshot examples/snapshot.mock.json --db "$demoDb" --organization-id ORG-DEMO --connection-id demo --contour test
python examples/integrations/import_notifications.py --snapshot examples/snapshot.mock.json --db "$demoDb" --organization-id ORG-DEMO --connection-id demo --contour test
```

В первый раз результат содержит `inserted=2, stored=2`, во второй
`inserted=0, unchanged=2, stored=2`. Изменение записи обновляет тот же ID.
Снимок с более старым временем наблюдения не откатывает новую запись.
Пустая выборка не удаляет ранее принятые уведомления.

```powershell
python -m unittest discover -s examples/integrations -p 'test_*.py' -v
```

17 тестов проверяют повторный прием, обновление, Base64, UTF-8, смену контекста,
старые снимки, потерю сессии, предел выдачи и запрет редиректа. Это проверки
клиента интеграции, не запуск 1С и не проверка живого портала.

## Читать действующий локальный API

Сначала настройте свою установку по [README](../README.md) и
[SESSION.md](SESSION.md), выполните явный сбор и `StartApi`. GET не запускает
новый сбор. Используйте OID, contour и connection_id из своего config.json.

```powershell
$bellRoot = Join-Path $env:LOCALAPPDATA 'EPGU Bell'
$consumerDb = Join-Path $env:LOCALAPPDATA 'Bell Integration/inbox.sqlite3'
python examples/integrations/import_notifications.py --base-url http://127.0.0.1:8778 --token-file "$bellRoot/session/api-token.txt" --db "$consumerDb" --organization-id YOUR_ORGANIZATION_OID --connection-id primary --contour test
```

Токен дает доступ только к локальной установке Bell. Это не ключ API ЕПГУ.
Пример не запрашивает пароль Госуслуг, не читает браузерные cookies и не
передает токен другому серверу. Начиная с rc.4 клиент читает страницы
локального API до конца и проверяет согласованность поколения базы.

Возврат `needs_user_action` означает, что импорт не выполнен; прежняя база
получателя сохраняется. Код завершения 2 требует внимания оператора.
Не превращайте ошибку или отсутствие сессии в успешную пустую выдачу.

## Подключить 1С

[BellReader.bsl](../examples/1c/BellReader.bsl) предназначен для отдельного
общего серверного модуля в тестовой базе. Он не меняет типовую конфигурацию
автоматически, не регистрирует обработку и не записывает документы.

Предлагаемый минимум платформы для примера: 8.3.10 с поддержкой JSON и
преобразования двоичных данных. Этот минимум не проверялся запуском.
Проверенные релизы платформы и типовых конфигураций пока отсутствуют.

Вызов из вашего серверного кода после переноса функций в общий модуль:

```bsl
Данные = BellReader.ПрочитатьИзAPI(
    ЛокальныйТокенИзВашегоЗащищенногоХранилища,
    ОжидаемыйOIDОрганизации, ОжидаемыйConnectionID, "test");
// Данные.Уведомления: ТаблицаЗначений.
// Данные.ПолнаяИстория = Ложь.
```

Модуль возвращает ID, заголовок, текст, отправителя, исходную дату,
прочитанность и ссылку. Дата остается исходной строкой с часовым поясом;
преобразование в Дату 1С должно учитывать принятую в вашей базе временную зону.
Текст показывайте обычной строкой, без выполнения HTML. Ссылки автоматически
не открываются. Вложения пример не скачивает.

Для файлового обмена используйте `ПрочитатьФайлJSON`. Путь относится к узлу,
на котором выполняется код 1С. Не передавайте клиентский путь серверу, если
сервер не имеет к нему доступа. Чтение файла не требует локального API-токена.

Вывод API можно сохранить один раз в папку обмена:

```powershell
$bellRoot = Join-Path $env:LOCALAPPDATA 'EPGU Bell'
$exchangeFile = 'C:/BellExchange/notifications.json'
$exchangeFolder = Split-Path $exchangeFile
New-Item -ItemType Directory -Force $exchangeFolder | Out-Null
$headers = @{Authorization = 'Bearer ' + (Get-Content -Raw "$bellRoot/session/api-token.txt").Trim()}
try {
    $response = Invoke-WebRequest http://127.0.0.1:8778/v1/notifications -Headers $headers -TimeoutSec 15
    [IO.File]::WriteAllText($exchangeFile + '.tmp', $response.Content, [Text.UTF8Encoding]::new($false))
    Move-Item -LiteralPath ($exchangeFile + '.tmp') -Destination $exchangeFile -Force
} finally {
    $headers = $response = $null
}
```

Файл содержит тексты уведомлений. Храните его в закрытой папке, не добавляйте
в Git и не прикладывайте к публичному отчету. Пример не создает расписание.

### Как записывать данные в 1С

В собственном регистре используйте ключ из connection_id, contour,
organization_id и ID уведомления. Повторный прием обновляет запись, а не
создает новую. Сначала разберите и проверьте весь пакет, затем выполняйте
запись транзакцией. При ошибке откатите пакет целиком. Сохраняйте время
наблюдения и не позволяйте старому снимку откатывать более новый.

Для бизнес-статуса сделайте отдельный реквизит с подтвержденным источником.
Текст колокольчика и `read_state` не равны статусу заявления. Сопоставление
уведомления с документом 1С требует отдельного проверенного идентификатора.

## CRM, n8n и похожие системы

Для пилота достаточно читать тот же JSON: проверить контекст и статус
снимка, развернуть `items[].record`, декодировать UTF-8/Base64 и сделать
upsert по составному ключу. Все строки остаются данными. Поля с отсутствующим
значением сохраняются как null, а не заменяются выдуманным статусом.

Python-пример создает таблицу `inbox` с декодированным текстом и исходной
записью в `record_json`. Эту границу удобно заменить адаптером к вашей CRM.
Готовый коннектор к конкретной CRM и проверенный workflow n8n не поставляются.

В ядре также есть outbox для заранее настроенного HTTP-получателя. Его
доставка требует явного действия. Приемник должен хранить Idempotency-Key:
после сетевого сбоя повторная доставка возможна. Текущий Windows-установщик
не предоставляет отдельный мастер настройки такого приемника; основной
путь этого руководства остается чтением API или файла.

## Ограничения синхронизации

В rc.4 `/v1/notifications` возвращает страницы
с курсором. Клиент Python обходит их до конца и проверяет поколение базы;
при изменении базы импорт не начинается. На старом rc.3 без курсора
сохраняется отказ при достижении лимита 1000 записей. Пример BSL пока
не обходит страницы и явно отказывает, если есть продолжение.
Подробности и защитные пределы: [PAGINATION.md](PAGINATION.md).
Ни один из этих путей не утверждает полноту истории портала.
`coverage.complete=false` нельзя заменять на true по отсутствию дублей.

Пример не выполняет полную проверку JSON Schema или криптографическую
аутентификацию снимка. Он рассчитан на свой локальный API и доверенную папку
обмена; проверяет контекст, основные поля и кодировку. Контракт и полная
схема находятся в [API.md](API.md) и [snapshot.schema.json](snapshot.schema.json).

Механизмы JSON и HTTP описаны фирмой 1С:
[средства работы с JSON](https://wonderland.v8.1c.ru/blog/sredstva-raboty-s-json/),
[работа с HTTP и JSON в примере 1С:Документооборота](https://v8.1c.ru/metod/article/rabota-1s-dokumentooborota-s-novoy-versiey-veb-servisa-morfer.htm).
